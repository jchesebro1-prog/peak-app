# Ask AI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Implement `docs/superpowers/specs/2026-10-13-ask-ai-design.md`. Ask AI in ⌘K is a Haiku research assistant (with Sonnet behind Try harder) over Peak data. It uses read-only lookup tools run with the user's permissions, and its proposal cards change nothing until the user confirms them.

**Architecture:**
- **Pure core:** refs, cards, page routes, conversation packing, NDJSON events, cost and loop limits.
- **Server:** read tools and the page context, plus an Anthropic tool-loop runner streamed as NDJSON from a POST route.
- **Client:** an Ask panel inside the existing Nav search dropdown, with confirms going through the app's existing actions.

**Tech stack:** Next.js 16 App Router, TypeScript, `@anthropic-ai/sdk` 0.128 (the beta messages stream), zod, the doc-store, and the assist layer (`src/lib/assist/*`).

## Global Constraints

**The spec is binding.** Its key values:

| What | Value |
|---|---|
| Feature key | `ask`, opt-in (default off) |
| Model slots | `ask` = `claude-haiku-5-5` (`ASSIST_MODEL_ASK`); `askHard` = `claude-sonnet-5-5` (`ASSIST_MODEL_ASK_HARD`) |
| Rate limit | `RATE_LIMITS.ask = 60` per hour |
| Route | `POST /api/assist/ask`, `maxDuration = 120`, requires `content-type: application/json`, NDJSON response, `no-store` |
| Context route | `GET /api/assist/ask/context?page=` |
| Body | `messages` ≤ 12 turns, each ≤ 8,000 chars, total ≤ 40,000; `page` ≤ 500 chars; `web`; `hard`; `retryOf` |
| Loop limits | ≤ 6 rounds and ≤ 12 tool calls; tool result ≤ 6,000 chars; wall clock 60 s Haiku / 90 s Sonnet; `max_tokens` 4,000; effort `low` Haiku / `medium` Sonnet |
| Web search | Only when `web`; `max_uses: 3`; $0.01 per search (`ASK_WEB_SEARCH_USD`) |
| Record references | `[[kind:id]]`, linked only when whitelisted by a `ref` event |

**Rules that bind every task:**

- Earlier turns are packed into the first user message as `<conversation>` and are never replayed as assistant messages.
- Model text and tool results are untrusted. There are no write tools. Cards sanitise against the refs this conversation has exposed. Confirms go only through the existing actions, which re-check permissions.
- One `assist_runs` row per question.
- `retryOf` marks the earlier run `discarded`, owner-checked, first decision wins.
- Ask is Claude-only. A local provider without a key refuses with "Ask AI needs the Claude API key."
- Client components import only actions, pure modules and types — no stores, no server modules.

### Task 3: Runner and route

**`src/lib/assist/ask-runner.ts`**
- `runAsk(input: AskBody, me: {id,name}, emit: (e: AskEvent) => void, deps: {client?, settings?, env?, now?, clock?, signal?})` implements spec §2's runner, steps 1–6. It uses the anthropic client (export `clientFor` from `anthropic.ts`, or add an injectable `AskModelClient` interface so tests can fake the stream).
- **Each round:**
  - Call `beta.messages.stream`. The params are built by a pure `buildAskParams({model, system, messages, tools, web, effort, maxTokens, fallbacks})`, which is unit-tested.
  - Emit `text` deltas.
  - Collect the `tool_use` blocks.
  - Validate each input with zod; on failure, return a tool_result with `is_error`.
  - Run read tools via `runReadTool`, and emit `ref` events, deduped per question.
  - The whitelist is server-side per request; the client never sends refs. It is built from this request's tool results and page context, plus up to 20 `[[kind:id]]` tokens found in the prior conversation text. Each of those tokens is re-checked with `runReadTool`'s access rule and emitted as a `ref` again, so the client can still link earlier answers.
  - The card sanitiser's `refs` and `emails` come from this whitelist and from the records' contact emails / participants.
  - Run proposal tools via `sanitizeCard`, then emit a `card` event.
  - Map web citations to `source` events (http/https only).
- **Web tool:** check the installed SDK's type names for `web_search_20260209` and `web_search_20250305`. Use 20260209 for Sonnet and 20250305 for Haiku unless the types or docs show Haiku supports the newer one. A 400 that mentions the tool means: retry the round once without web, and add the note.
- **Wrap-up:** stop-reason handling, the limits, `pause_turn`, abort via `signal`, and the wall clock. Then log one run (fields per spec §2.6) with `createRun`. When `retryOf` is set, mark that run `discarded` using the existing outcome setter with an owner check (find it in `src/lib/stores/assist-runs.ts`). Emit `done` with the runId.

**`src/app/api/assist/ask/route.ts`**
- `export const maxDuration = 120`.
- Content-type check (415), then `requireUser` inside try, then the body parse (400 on failure).
- Return a `ReadableStream` that runs `runAsk` and writes encoded events. `request.signal` aborts the run. Headers: `content-type: application/x-ndjson; charset=utf-8` and `cache-control: no-store`.
- Gate failures become a single `error` event with a 200 status, so the client handles everything one way. 4xx is only for a malformed request.

**`recordAskCardAction(runId, kind)`:** a server action in `src/lib/assist/ask-actions.ts` with `"use server"`. It owner-checks, sets outcome `accepted` if it is still null, and appends `kind` to `outcomeDetail.confirmed` (≤ 20).

**Fake-client runner tests:**
- a tool round-trip with a `ref` emitted;
- an invalid tool input becomes `is_error`;
- the round and tool caps force a final no-tools round;
- a refusal;
- the wall-clock stop;
- abort still logs;
- the web tool is present only when `web`;
- `hard` uses the Sonnet slot;
- a card's unknown ids are dropped;
- `retryOf` is discarded and owner-checked;
- the gate refuses when off;
- cost sums the rounds and the web searches.

**Pins:** the route's `maxDuration` 120 and content-type check. **Gates** include `next build`. **Commit.**
