# The Grid: Generated Base Sheet — Implementation Plan (#38/#41)

Planning pass for punch #38, run against the narrowed spec
`docs/superpowers/specs/2026-08-09-grid-base-sheet-estimator-split-design.md`
(which supersedes the original 2026-07-25 spec for this build — both open
questions from the original are already resolved there). Recon executed as
real code reads, not assumption; task breakdown follows the spec's own 6
build tasks.

## Recon findings (confirmed vs. drifted from the 2026-08-09 spec)

**Confirmed accurate:**
- `src/lib/design/venue-dims.ts` is exactly as the spec describes:
  `proWidthFt`/`stageWidthFt` are already distinct, documented fields, no
  bare `width`. The "dims trap" is genuinely resolved. Nothing to build here.
- Categories toggle (#48/D125) is fully shipped (`GridPlacement.category`,
  `grid-scopes.ts`). Confirmed not to re-plan.
- The Grid's derived-riser slice (`/design/grid/[id]/riser/page.tsx` →
  `src/lib/design/grid-riser.ts`) is a genuine, working "derive live from
  Grid instances" precedent — it reads `project.placements`/`routes`/`spaces`
  fresh on every load with zero stored state. This is the template Task 4
  should copy for the equipment/lineset schedules, not new architecture.
- A Grid project already supports multiple sheets today:
  `GridProject.sheetIds: string[]`, `addSheet()` appends, `listSheets()`
  returns them in order (`src/lib/stores/grid-projects.ts:150-186, 265-284`).
  Task 3 (separate sheet on real-plan-upload) is close to free —
  `addSheetAction` already does this; nothing structural is missing.

**Real drift the spec didn't anticipate:**

1. **A "generated base sheet" already exists in shape but is dims-blind.**
   `createProject()` (`grid-projects.ts:205-249`) unconditionally creates a
   *generic* blank white-rectangle SVG sheet plus three hardcoded,
   dims-independent starter `Spaces` ("Audience view", "Stage",
   "FOH / control" at fixed normalized coordinates) for every new project,
   before any dims are ever collected. Task 1 is "make the existing default
   sheet venue-shaped instead of a fixed blank rectangle," not "add a base
   sheet."
2. **The dims-intake UI already exists, fully wired to the reused engine.**
   `GridIntake` (`design/grid/[id]/grid-intake.tsx`) is shown post-creation
   whenever `project.intake.complete` is false (`page.tsx:49`), and already
   imports `DIMSCHEMA`, `VENUES`, `compute`, `sizedDims`, `defaultAState`
   from `design/quick/engine.ts` — the exact "estimator's plan-view logic"
   the spec references, and even live-previews `compute(a)` as an
   "Autogenerated brief." Saving calls `saveGridIntakeAction` →
   `saveGridIntake()` (`grid-projects.ts:252-258`), which only patches
   `project.intake` — never sheets/spaces/calibration. Task 1's real gap is
   narrow: hook sheet/space/calibration generation onto that existing save
   path.
3. **An inert, already-built toggle is exactly the seeding gate needed.**
   The intake form has a working "Generate from measurements as I work"
   checkbox (`measurementBased`, default `true`), saved into
   `project.intake.measurementBased`, read by nothing anywhere (confirmed by
   grep). Tasks 1/2 should wire this up rather than invent a new toggle.
4. **The estimator's plan-view is a decorative room diagram, not device
   instances — "seeding" is a real translation job.** `plan-svg.tsx`'s
   `buildPlan()` draws walls/doors/seating/proscenium and schematic marks,
   entirely separate from catalog parts. Quantities live in `compute()`
   (`quick/engine.ts:478-680`), pure `dBlk`-style parametric guessing — the
   exact problem the spec wants killed. Task 2 needs a new mapping from
   `compute()`'s system booleans/counts to real catalog `partId`s and
   `GridPlacement`s — nothing like it exists today.
5. **`GridPlacement` insertion is single-item only.** `addPlacement()`
   (`grid-projects.ts:311-327`) patches one placement per call. Task 2's
   seeding needs a new bulk `addPlacements()`.
6. **Lineset Builder has zero structural linkage to Grid projects today.**
   It saves into a completely separate `studio_designs` blob keyed only by
   `id`/`customerId`/`customer` — no `gridProjectId`, no shared site/venue
   id. `generateLineset()` is a pure function, easy to call, but there's no
   record pointing a Grid project at a saved lineset design. Task 4 needs an
   explicit link (e.g. `linesetDesignId` on `GridProject`), not just "read
   the shared VenueDims."
7. **The estimator/Grid merge is further along than the spec assumes.**
   `src/lib/stores/designs.ts` already has `layoutMode: "quick" | "manual"`
   and `gridProjectId`; `createManualDesignAction` already creates a linked
   Grid project for "manual" designs. This is the natural anchor for Task
   5's seam — but it surfaces a real bug: **`DesignRecord.budget` is never
   written for manual-mode designs** (confirmed by grep — nothing calls
   `updateDesign(id, { budget })` from any Grid action). Every Grid-linked
   design shows a stale/zero Budget on `/design/designs` forever until
   promoted to a quote.
8. **The only full Grid BOM total lives inside a mutating server action.**
   `createDraftQuoteAction` (`design/grid/[id]/actions.ts:543-704`) is the
   sole place `bomLines`/`bomTotals`/`routeLines`/`curtainLines`/labor
   pricing assemble into one total, gated behind `requireUser()` and always
   writing a real Quote as a side effect. Task 5 needs a pure
   `computeGridBom(project, catalog, tier, laborLines)` extracted from it.
9. **The estimator's own "Schedule" tab is a non-functional stub deferring
   to a vestigial "Manual layout" toggle**, both predating the real Grid
   merge. `quick-design-client.tsx`'s Schedule view (`:837-848`) is an
   empty-state dead end with copy describing Grid's already-shipped
   capabilities as a future promise; the toggle doesn't link to `/design/grid`
   at all. Narrows Task 6's parity checklist and adds a cleanup item not in
   the spec's 6 tasks but required before Task 6 can be called done.

## Task 1 — Generated base sheet
Replace the dims-blind default sheet with one rendered from
`VenueDims`/`AState`, correctly scaled, no calibration step.

**Files:** `src/lib/stores/grid-projects.ts` (new `generateBaseSheet()`
using `buildPlan()` + a new markup serializer, auto-written `Calibration`);
`src/app/(app)/design/quick/plan-svg.tsx` (new `renderPlanSvgMarkup()`
string-builder export, no `handles`/drag math); `src/app/(app)/design/grid/[id]/actions.ts`
(`saveGridIntakeAction` hook); `grid-projects.ts` `createProject()` stops
pre-seeding the generic blank sheet when intake will run immediately after.

**Sequencing:** first; no dependency. Task 2 depends on this.

**Acceptance:** new Grid project → enter `VenueDims` → base plan appears,
correctly scaled, zero uploads, zero calibration prompts.

## Task 2 — Seeding action ("generate starting layout from dims")
**Files:** new `src/lib/design/grid-seed.ts` (maps `compute(a)` output to
catalog `partId`s + normalized positions via `prosGeom`/`churchGeom` —
highest-risk/most-judgment part of the build, reuse `catalog-taxonomy.ts`/
`grid-scopes.ts` category mapping rather than inventing a parallel one);
`grid-projects.ts` new bulk `addPlacements()`; `grid/[id]/actions.ts` new
`seedStartingLayoutAction` (additive re-run — tag seeded placements so a
second run detects "already seeded" rather than duplicating); `editor.tsx`
new trigger button gated on `project.intake?.measurementBased`.

**Sequencing:** depends on Task 1. Independent of Tasks 3–6.

**Acceptance:** seeds editable drapes/electrics/etc.; re-run adds rather
than silently replacing, with a confirm prompt first.

## Task 3 — Real-plan-upload creates a separate sheet
**Files:** `grid/[id]/actions.ts` (`addSheetAction`) + upload UI in
`editor.tsx`. Almost entirely reuse — `addSheet()` already appends to
`sheetIds` without touching placements. New: UI/copy making the
separate-sheet behavior explicit on upload.

**Sequencing:** structurally independent; only meaningfully testable once
Task 1 exists.

**Acceptance:** uploading a plan PDF onto a project with an existing base
sheet produces a second, separate sheet; the base sheet is unchanged.

## Task 4 — Artifact derivation: equipment schedule, lineset schedule, riser
**Files:** `grid/[id]/schedule/page.tsx` (already derives a per-space
equipment schedule live from placements/spaces/routes — treat as reuse,
extend only if Task 6's parity checklist finds a real gap); `grid/[id]/riser/page.tsx`
+ `src/lib/design/grid-riser.ts` (already the derived-riser slice; open
design question — does Grid's riser need to also synthesize infrastructure
nodes like the estimator's `buildRiser()` from placed devices' catalog
categories, or is that a distinct concern? Not resolved by the spec —
needs a call before building, not a silent pick); new `linesetDesignId?`
field on `GridProject` + a picker UI (mirror the `specHref`-via-engagement
pattern in `page.tsx:69-71`) + new lineset-schedule surface that loads the
linked `StudioDesign` and runs `generateLineset()`.

**Sequencing:** depends on Tasks 1+2 for real instances (schedule/riser
already handle empty state gracefully). Lineset-schedule linkage has no
dependency on 1/2/3 and could be built in parallel.

**Acceptance:** equipment schedule, lineset schedule, and riser all
regenerate correctly after an edit to Grid instances; Lineset Builder
itself unaffected.

## Task 5 — Estimator seam: "use Grid BOM if present, else price parametrically"
**Files:** extract the BOM-assembly block from `createDraftQuoteAction`
into a pure `computeGridBom()` (new module, e.g. `src/lib/design/grid-bom.ts`)
callable by both the existing quote-mint flow and a new read-only path;
`src/lib/stores/designs.ts` — when `layoutMode === "manual"` and the linked
`GridProject` has placements/routes, use the Grid BOM total instead of the
parametric one; fix the confirmed `DesignRecord.budget` bug (compute live
on read from the linked Grid project, preferred over a second stale-cache
field). `/design/quick` itself needs no seam — it's explicitly numbers-only,
unchanged by this work.

**Sequencing:** depends on Tasks 1/2 for a real BOM to consume; otherwise
independent, buildable in parallel with Task 4.

**Acceptance:** quick estimator still produces a budget from dims alone
with no Grid BOM; uses the Grid BOM when one exists (verify via the Designs
dashboard, where the currently-broken `budget` field lives).

## Task 6 — Retire estimator-side drawing outputs once parity is reached
**Parity checklist:** Plan tab (real output — Task 1's base sheet is the
equivalent); Schedule tab (already a dead stub, nothing to reach parity
with); Riser tab (real output, different node shape than Grid's — resolve
Task 4's open question first, or explicitly decide the two riser views
serve different purposes); the vestigial "Manual layout"
toggle/banner in `quick-design-client.tsx:652-664` (stale copy, doesn't
link to `/design/grid` — not one of the spec's 6 tasks but a prerequisite
cleanup for calling this task done).

**Files:** `quick-design-client.tsx` (remove Plan/Schedule/Riser tabs +
banner once parity confirmed), `plan-svg.tsx` (keep `buildPlan`/`prosGeom`/
`churchGeom` — Task 1 depends on them — remove `handles`/drag-math only if
verified dead), `engine.ts` (`buildRiser` removal only if Task 4 fully
subsumes it), `ViewKey` type.

**Sequencing:** last; strictly depends on Tasks 1, 2, 4 shipped and
verified in real use, not just code-complete. Go/no-go gate, not an
independently-verifiable feature.

## Critical files
- `src/lib/stores/grid-projects.ts` — `GridProject`/`GridSheet` model,
  `createProject`, `addPlacement`/`addSheet`.
- `src/app/(app)/design/quick/plan-svg.tsx` — `buildPlan`/`prosGeom`/
  `churchGeom`, needs the new markup-serializer export.
- `src/app/(app)/design/quick/engine.ts` — `compute()`, `AState`,
  `DIMSCHEMA`, `buildRiser()`.
- `src/app/(app)/design/grid/[id]/actions.ts` — `saveGridIntakeAction`
  (Task 1's hook) and `createDraftQuoteAction` (source of Task 5's pure
  BOM function).
- `src/lib/stores/designs.ts` — `DesignRecord.layoutMode`/`gridProjectId`/
  `budget`.

No schema/migration changes anywhere in this plan — every new field lives
inside the existing `grid_projects`/`designs` doc-store JSONB blobs, not a
new relational column or collection.
