# #348 Slice 4: Vendors implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to work through this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A vendor quote is tied to a real vendor **company**. The modal's Vendor field becomes a picker over vendor and manufacturer companies, with a typed-name fallback. Saving a quote with a company adds a `vendor` party to the estimate, once. A vendor's company page lists "Quotes we've received". In the Inbox:
- **File to estimate / project…** files a thread to an estimate or project, keeps the vendor as the thread's company and adds the vendor party.
- **Add as vendor quote…** on a PDF opens the Estimator with the vendor quote modal pre-filled: the vendor company, the quote # read from the subject, and the PDF copied server-side to the vendor-quote Blob path.

A staff-only **Vendors card** on Build package and Send & track groups each vendor's quotes and filed emails. A project's **Procurement** tab reads the estimate's vendor quotes and threads, plus threads filed to the project. Read the PDF is slice 5. The modal gets an empty slot for its button.

**Architecture:**
- **Rules.** Every rule is a pure function in `src/lib/vendor-quotes/rules.ts`, which is browser-safe.
- **Writes.** Vendor parties go only through `addParty` (slice 1). Links go through the existing thread writers: `linkThread` (`src/lib/gmail/linking.ts:282`) and `setLink` (`src/lib/stores/comms.ts:2010`).
- **Gmail attachments are not stored today.** `parseInbound` (`src/lib/gmail/mime.ts:187`) keeps only the body. This slice records attachment metadata on import (part id, name, mime, size), never the bytes. Older mail is listed lazily for the owner. Bytes are fetched on demand by one server-side broker, `readThreadAttachment`. It checks `canSeeThread` and that the attachment belongs to that message on that thread. Both the new download route and the "Add as vendor quote" copy use it.
- **Hand-off.** It is a URL reference, `?vq=<threadId>~<messageId>~<index>`, resolved by the broker when the Estimator opens (D-next-6). Nothing is stored as a draft, and only `{ blobPath, name, mime }` reaches the browser.
- **Thread lists.** Vendor-thread lists read with `listDocsWhere("comms", …, canSeeThreadCond(viewer))` and are re-checked with `canSeeThread` in JS, so the #341 rules are applied twice.

**Tech stack:** Next.js 16, TypeScript, doc-store, the `test:specs` harness.

**Spec:** `docs/superpowers/specs/2026-10-14-estimate-parties-and-bids-design.md` §3.7 (`vendorCompanyId`, the party on save) and §6 (Vendors), plus the company-page line in §4. `VendorQuote.extracted` and Read the PDF (§7) are slice 5.

export type VendorQuoteLike = {
  id: string;
  vendor?: string;
  vendorCompanyId?: string | null;

const COMPANY_ID_RE = /^\S{1,120}$/;
const REF_PART = /^[A-Za-z0-9_-]{1,64}$/;

/** Narrow a stored `quote.vendorQuotes` blob (typed `unknown` on Quote). */
export function asVendorQuotes(raw: unknown): VendorQuoteLike[] {
  return Array.isArray(raw) ? (raw as VendorQuoteLike[]).filter((v) => !!v && typeof v === "object" && typeof v.id === "string") : [];
}

/** Distinct vendor company ids, first-appearance order, blanks ignored. */
export function vendorCompanyIdsOf(vqs: readonly VendorQuoteLike[]): string[] {
  const out: string[] = [];
  for (const v of vqs) {
    const id = typeof v.vendorCompanyId === "string" ? v.vendorCompanyId.trim() : "";
    if (id && !out.includes(id)) out.push(id);
  }
  return out;
}

/** Companies this save introduces (D-next-2: the vendor party is added once — when a company first appears). */
export function newVendorCompanyIds(prior: readonly VendorQuoteLike[], next: readonly VendorQuoteLike[]): string[] {
  const had = new Set(vendorCompanyIdsOf(prior));
  return vendorCompanyIdsOf(next).filter((id) => !had.has(id));
}

/** Server-side stamping (D-next-3): addedAt is the prior record's (absent stays absent — legacy untouched), `now` for a
 *  new id; a malformed vendorCompanyId / fromThreadId is dropped. Never trusts the browser's addedAt. */
export function stampVendorQuotes<T extends VendorQuoteLike>(prior: readonly VendorQuoteLike[], next: readonly T[], now: number): T[] {
  const priorAt = new Map(prior.map((v) => [v.id, v.addedAt] as const));
  return next.map((v) => {
    const out: T = { ...v };
    const at = priorAt.has(v.id) ? priorAt.get(v.id) : now;
    if (typeof at === "number" && Number.isFinite(at) && at > 0) out.addedAt = at;
    else delete out.addedAt;
    const co = typeof v.vendorCompanyId === "string" ? v.vendorCompanyId.trim() : "";
    if (co && COMPANY_ID_RE.test(co)) out.vendorCompanyId = co;
    else delete out.vendorCompanyId;
    const th = typeof v.fromThreadId === "string" ? v.fromThreadId.trim() : "";
    if (th && REF_PART.test(th)) out.fromThreadId = th;
    else delete out.fromThreadId;
    return out;
  });
}

/** Drop a vendorCompanyId that isn't a live vendor company (the typed `vendor` name stays). */
export function keepLiveVendorCompanies<T extends VendorQuoteLike>(vqs: readonly T[], live: ReadonlySet<string>): T[] {
  return vqs.map((v) => {
    if (!v.vendorCompanyId || live.has(v.vendorCompanyId)) return v;
    const out: T = { ...v };
    delete out.vendorCompanyId;
    return out;
  });
}

const SUBJECT_QUOTE_RE = /\b(?:quote|quotation|qte?|proposal)\b\.?\s*(?:#|no\.?|number|num\.?|nbr\.?)?\s*[:#]?\s*([A-Z0-9][A-Z0-9._/-]{0,39})/gi;

/** The vendor's quote number when the subject makes it obvious (a token with a digit after quote/quotation/qt/proposal), else "". */
export function quoteNumberFromSubject(subject: string | null | undefined): string {
  for (const m of (subject || "").matchAll(SUBJECT_QUOTE_RE)) {
    const tok = m[1].replace(/[._/-]+$/, "");
    if (/\d/.test(tok)) return tok;
  }
  return "";
}

export function isPdfAttachment(a: { name?: string | null; mime?: string | null }): boolean {
  return (a.mime || "").toLowerCase().split(";")[0].trim() === "application/pdf" || /\.pdf$/i.test((a.name || "").trim());
}

export type ThreadAttachmentRef = { threadId: string; messageId: string; index: number };
export function threadAttachmentRef(r: ThreadAttachmentRef): string {
  return `${r.threadId}~${r.messageId}~${r.index}`;
}
export function parseThreadAttachmentRef(raw: unknown): ThreadAttachmentRef | null {
  if (typeof raw !== "string" || raw.length > 140) return null;
  const parts = raw.split("~");
  if (parts.length !== 3) return null;
  const [threadId, messageId, i] = parts;
  if (!REF_PART.test(threadId) || !REF_PART.test(messageId) || !/^\d{1,2}$/.test(i)) return null;
  const index = Number(i);
  return index < ATTACHMENTS_PER_MESSAGE_MAX ? { threadId, messageId, index } : null;
}

/** A thread's card row — subject, last message's author/time, unread. Never the body. */
export function vendorThreadRow(t: { id: string; customerId: string; subject?: string; unread?: boolean; messages?: ReadonlyArray<{ at?: number; author?: string }> }): VendorThreadVM {
  let last: { at?: number; author?: string } | null = null;
  for (const m of t.messages || []) if (!last || (m.at || 0) >= (last.at || 0)) last = m;
  return { id: t.id, companyId: t.customerId, subject: (t.subject || "").trim() || "(no subject)", lastAt: last?.at || 0, lastFrom: last?.author || "", unread: !!t.unread, href: `/inbox?thread=${encodeURIComponent(t.id)}` };
}

function quoteRow(v: VendorQuoteLike): VendorQuoteRowVM {
  return {
    id: v.id, quoteNumber: v.quoteNumber || "", description: v.description || "", total: typeof v.total === "number" ? v.total : 0,
    addedAt: typeof v.addedAt === "number" ? v.addedAt : null, hasFile: !!(v.attachment && (v.attachment.blobPath || v.attachment.dataUrl)),
    fromThreadId: v.fromThreadId || null,
  };
}

/** Per vendor company: its vendor quotes + filed threads. Companies by name; typed-only (legacy) groups last. */
export function vendorCardGroups(input: { vendorQuotes: readonly VendorQuoteLike[]; companies: readonly VendorCompanyVM[]; threads: readonly VendorThreadVM[] }): VendorCardGroup[] {
  const byCo = new Map<string, VendorCardGroup>();
  const typed = new Map<string, VendorCardGroup>();
  const co = (id: string, name: string) => {
    let g = byCo.get(id);
    if (!g) byCo.set(id, (g = { key: `co:${id}`, companyId: id, name, href: `/companies/${encodeURIComponent(id)}`, quotes: [], threads: [] }));
    return g;
  };
  for (const c of input.companies) co(c.id, c.name);
  for (const v of input.vendorQuotes) {
    if (v.vendorCompanyId) {
      co(v.vendorCompanyId, (v.vendor || "").trim() || v.vendorCompanyId).quotes.push(quoteRow(v));
      continue;
    }
    const name = (v.vendor || "").trim() || "Vendor";
    const k = name.toLowerCase();
    let g = typed.get(k);
    if (!g) typed.set(k, (g = { key: `typed:${k}`, companyId: null, name, href: null, quotes: [], threads: [] }));
    g.quotes.push(quoteRow(v));
  }
  for (const t of input.threads) byCo.get(t.companyId)?.threads.push(t);
  for (const g of byCo.values()) g.threads.sort((a, b) => b.lastAt - a.lastAt);
  const byName = (a: VendorCardGroup, b: VendorCardGroup) => a.name.localeCompare(b.name);
  return [...[...byCo.values()].sort(byName), ...[...typed.values()].sort(byName)];
}

/** "Quotes we've received" rows for one vendor company, newest first (undated last). */
export function quotesReceivedRows(
  companyId: string,
  quotes: ReadonlyArray<{ id: string; number: string; name: string; customer: string; status: string; href: string; vendorQuotes: unknown }>
): QuoteReceivedRow[] {
  const out: QuoteReceivedRow[] = [];
  for (const q of quotes)
    for (const v of asVendorQuotes(q.vendorQuotes))
      if (v.vendorCompanyId === companyId)
        out.push({
          key: `${q.id}:${v.id}`, quoteId: q.id, estimate: q.number, job: [q.name, q.customer].filter(Boolean).join(" — "), href: q.href,

## Risks and how this plan contains them

- **Thread visibility leaks.**
  - **Vendors card and Procurement.** Thread lists are cut in SQL with `canSeeThreadCond(viewer)` (the #341 mirror) and re-checked with `canSeeThread`. Drafts and deleted threads are excluded for everyone. Only subject, last author and time, and `unread` are shipped (test: no `body`, `messages` or `snippet` keys).
    - An unfiled automatic sender match never appears, because it needs the work link.
    - A thread a viewer can't see adds nothing, not even a count. Group counts are computed client-side from the already-filtered list.
  - **Broker and download route.** Both use one function, `readThreadAttachment`. It requires `canSeeThread` and gives an identical refusal or 404 for missing and invisible threads (no oracle). The attachment index is resolved on the stored message of that thread, so a caller can't name another thread's file.
  - **Writes.** `fileThreadAction` and `listThreadAttachmentsAction` live in an audited `ACTION_FILES` file and call `ownThread(` (the #341 source audit fails otherwise).
  - **Filing shares by design.** The work link makes the thread visible to staff, which is exactly #341's "deliberate link". The File dialog says so (`fileShares`).
- **Attachment size and the 4.5 MB ceiling.**
  - The broker never receives bytes from the browser. It fetches from Gmail (`attachments.get` under `gapi`'s timeout; the Estimator page's `maxDuration` is 120) or decodes the stored data-URL, then writes to Blob.
  - The cap is 25 MB, checked before the fetch on the stored size and again on the bytes.
  - **Residual risk:** streamed *responses* over 4.5 MB, from the new download route and from the existing vendor-quote proxy now that files can exceed 4 MB. Verify on a preview deploy with a PDF over 5 MB (the PUNCHLIST prod check). The fallback is one constant: set the broker cap to `VENDOR_UPLOAD_MAX_BYTES`.
  - With no Blob, a data-URL is used only inside `VENDOR_ATTACHMENT_BUDGET`, so a save can never exceed the 1200 kb server-action body.
- **Duplicate vendor parties.** These are impossible by construction (`partyId` is derived from the record, company and role; `addParty` returns `existed`). "Once" semantics mean a deliberate removal sticks, and removal is refused while a live vendor quote names the company. That keeps "Quotes we've received" (indexed by party rows) complete for every live quote.
- **Legacy vendor quotes without a company.** They are untouched: no party, absent from the vendor page, shown in the Vendors card under "Not linked to a vendor company", and linkable via Edit (the typed mode's "Link to a vendor company").
- **Gmail attachment ids.** They aren't stable, so the plan stores `partId` and re-resolves the attachment id at fetch time. A message deleted in Gmail gives a 404, which stamps `attsListed` (no retry loop) and makes the broker say `copyFailed`.
- **Hand-off races.** The `?vq=` param is stripped before the action runs. The prefill applies only while the open draft is the seeded id. A Blob copy abandoned with its form is orphaned, the same accepted precedent as an abandoned upload.
- **Quota.** The lazy listing makes at most 10 `messages.get` calls (5 units each) per thread open, once per message, and only for the owner's own threads.
