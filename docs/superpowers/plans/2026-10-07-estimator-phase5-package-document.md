# Estimator — Phase 5 (Build package document editor) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Word-like client document on the Build package step (TipTap) whose saved JSON replaces the per-system narrative on the customer PDF / online estimate / package page — numbers as live chips, product paragraphs linked to the catalog with Save to product, photo placement, drag from the BOM — while quotes without a document print exactly as today.

**Architecture:** A pure `src/lib/package-doc/` module owns the schema (as data), the server-side validator, the seed builder, chip resolution, gaps and plain-text helpers. A server-safe React renderer (`PackageDocView`) prints the document inside `QuoteDocument`; the editor is a client-only TipTap component (dynamically imported) with custom extensions/NodeViews mirroring the same schema. The document lives in the estimator hook beside `sections` and saves in `spec.document`.

**Tech Stack:** Next.js 16, React 19, TypeScript; `@tiptap/react`, `@tiptap/pm`, `@tiptap/starter-kit` 3.x (MIT; no Pro extensions); spec harness `scripts/test-review-and-spec.ts`.

**Spec:** `docs/superpowers/specs/2026-10-07-estimator-four-steps-design.md` §12.

## Global Constraints

- Storage: `spec.document?: PackageDoc` (ProseMirror JSON `{ type: "doc", content: [...] }`, `version: 1`). Saved via `saveQuoteAction` (add to `SavePayload`, `QuoteExtras.spec`, the rebuilt `spec` literal — it is rebuilt as `{ sections, mobs, groups }` today and would drop it). Revision snapshots copy `spec` whole.
- Schema (exact): blocks `paragraph`, `heading` (attrs `level` 1|2|3), `bulletList`, `orderedList`, `listItem`, `pageBreak` (atom), `priceTable` (atom), `productBlock` (attrs `sectionId`, `lineKey`, `sku`, `photo: { show: boolean; align: "left" | "right" | "full"; width: number /* 25–100 */ }`; content paragraph+); inline `text` (marks `bold`, `italic`), `hardBreak`, `chip` (attrs `kind: "systemPrice" | "systemName" | "lineQty" | "quoteNumber" | "grandTotal"`, `ref: string` — sectionId for system kinds, `sectionId:lineKey` for lineQty, "" otherwise). Caps: ≤ 2,000 nodes, JSON ≤ 200 KB, ≤ 20,000 chars of text per block; unknown nodes/marks/attrs dropped; invalid docs → `null` (treated as no document).
- When `spec.document` is a valid non-empty doc, `QuoteDocument` replaces the system-bands narrative body with `PackageDocView`; header, totals, alternates block, optional-additions box, terms, signature and the itemized appendix unchanged. No document → byte-identical output to before (prove with a fixture captured from base, like #P2b).
- Chips resolve at render from `QuoteDocumentProps` (`sections`, `t`, `quoteId`): `systemPrice` = `fmt(systemSellTotal(sec))`, `systemName` = `sec.name`, `lineQty` = the line's `qty` (+ unit), `quoteNumber` = `quoteId`, `grandTotal` = `fmt(t.grand)`. Missing ref → client outputs render nothing; editor shows amber `removed`.
- Photos: a product block with `photo.show` uses the same photo resolution as key products (primary part image → manufacturer image → placeholder); print = data URIs (extend `keyProductPhotoDataUris` / `photoSkusOf` to include document product skus), web = the revision-scoped photo routes (extend `photoDocForRevision` allowlist to document skus).
- Product-block tag copy (exact): `<label> · from product` / `<label> · edited here`; buttons `Save to product`, `Revert`; flag `No longer in BOM`; chip `removed`. Left pane titles `Gaps`, `BOM`, `Library`; buttons `Start the document`, `Remove document`; library items `Price table`, `Page break`, `Not included list`.
- Editor is client-only and dynamically imported (`next/dynamic`, `ssr: false`) so TipTap never enters other pages' bundles or server renders.
- Cover PDF unchanged in Phase 5 (it keeps using `coverText` / narrative fields).
- Gates per task: `npx tsc --noEmit` 0; scoped eslint clean (never `npm run lint`); `npm run test:specs` FAIL 0 (report PASS); `npx next build` on tasks touching client components/routes. Never `git stash`; never touch `.data/`. Trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Numbers assigned in Task 6.
