# The Grid: options model + intake branch (Spec 1 of 3)

**Date:** 2026-09-21 · **Status:** approved by Jeff in brainstorm, awaiting plan
**Builds on:** `2026-08-09-grid-base-sheet-estimator-split-design.md` (base sheet, D145),
`2026-09-20-manual-mode-scope-targets-design.md` (Scope panel, D139), D147 (placeholder seeding)

## Why this exists

Jeff opened a new "Manual layout · The Grid" design on 2026-09-21 and expected what the
intake promised: an autogenerated Good / Better / Best design from venue type and
dimensions. What shipped under #38 Tasks 1–2 delivers only the venue outline as a base
sheet; generation is a hidden "Generate starting layout" button that paints Lighting and
Curtains as *placeholder* devices with no catalog part, and it ignores the tier the intake
collected. The real tiered engine and finished plan drawing still live in Quick canvas, a
separate entry point. Two drawing paths, neither complete.

The agreed end state (this brainstorm) is one path:

1. New design opens the Grid intake: venue type + dimensions, then **Auto-estimate** or
   **Manual placement**.
2. Manual → cover page → editor with a scaled base sheet and one empty option.
3. Auto → systems → refinement step (three tier cards with live totals, per-system
   choices, every BOM line pre-filled with the tier's catalog part or assembly, swappable).
4. Generate → three **options** (Good / Better / Best) land on the base sheet as real
   placements. Plan, schedules, riser, BOM and price derive per option.
5. One **proposal document** shows all options; each option can mint its own draft quote.

That is three specs, built in order:

| Spec | Scope |
| --- | --- |
| **1 (this doc)** | Options on a Grid project + editor switcher + per-option quotes; intake reshaped for the Manual path; broken seeding button removed. Manual works end to end. |
| 2 | Tier part map in Estimating Rules; Auto refinement step; generation into three options; plan positions for Audio / Video / Rigging; "New design" rerouted to the intake; Quick canvas retired from New design. |
| 3 | Design proposal document (all options side by side, cites per-option quote numbers). |

Decisions locked in the brainstorm and carried across all three specs:

- **Final Auto artifact = real devices on the Grid canvas** (not the Quick Design static
  plan). Consistent with the standing "Grid instances are the only source of plans" rule.
- **Manual asks for venue type + dimensions only** before opening the editor.
- **Tier proposes parts, the user swaps.** Map targets may be catalog parts *or* Grid
  assemblies (fixtures, controls). `AState.fixtureAssemblies` is the existing seam.
- **New design goes straight to the Grid intake** once Auto exists (Spec 2).
- **Options are first-class variants**, not revisions (history) and not sibling projects.
- **One proposal document, quotes minted per option** — quotes get no alternates concept.

## Section 1 — Options data model

`GridProject` gains:

```ts
export type GridOption = {
  id: string;            // 'opt-' + random
  name: string;          // "Design", "Good", "Better", "Best", or user text
  tier?: TierKey;        // set by the Auto generator (Spec 2); absent on hand-made options
  quoteId: string | null;
  createdAt: number;
};
type GridProject = {
  // ...existing
  options?: GridOption[];   // absent on pre-spec docs — normalized on read, see below
};
```

`GridPlacement` and `GridRoute` each gain `optionId?: string`.

**Shared vs per-option.** Sheets, calibrations, spaces, revisions, intake, scopeInputs,
siteId/venue and customer stay at project level and are shared by every option — the room
and its scale don't change between tiers. Only placements and routes are per option.

**Read-side normalization (no data rewrite).** `getProject`/`listProjects` pass every doc
through `normalizeOptions(doc)`:

- No `options` or empty → `[{ id: "opt-base", name: "Design", quoteId: doc.quoteId ?? null,
  createdAt: doc.createdAt }]`.
- Any placement or route without `optionId` → reads as `options[0].id`. (Stamped in memory
  only; the stored doc is untouched until that placement is next written.)
- `doc.quoteId` is kept as a mirror of `options[0].quoteId`; `setOptionQuote` on the first
  option also writes `doc.quoteId` so every existing reader of `project.quoteId` (Designs
  dashboard, promote action, Quotes hub back-links) keeps working unchanged.

**Invariants.** A project always has ≥ 1 option. Deleting the last option is refused.
Option ids are unique per project. A placement/route's `optionId` always names an existing
option (delete option removes its members in the same patch).

**Revisions.** `GridRevision` gains `options?: GridOption[]`, captured by `pushRevision`
next to placements/routes. `restoreRevision` restores `options` too; a pre-spec revision
(no `options`) restores as a single default option and its placements/routes are read as
members of it — same rule as the project-level normalization. Sheets remain referenced,
not copied (D109 unchanged).

## Section 2 — Store, actions, quotes

**New store functions** (`src/lib/stores/grid-projects.ts`):

| Function | Behaviour |
| --- | --- |
| `addOption(projectId, { name, copyFromOptionId?, by })` | Appends an option. With `copyFromOptionId`, deep-copies that option's placements and routes with **new ids**, remapping `fromPlacementId`/`toPlacementId` on copied routes to the new placement ids. Curtain placements copy their curtain payload. Returns the new option. |
| `renameOption(projectId, optionId, name, by)` | Trimmed, non-empty. |
| `removeOption(projectId, optionId, by)` | Refused (`{ ok:false, reason:"last-option" }`) when it is the only option. Otherwise removes the option and every placement/route tagged with it in one patch. Cuts a `manual` revision first ("Auto-saved before removing option X"). Does not touch quotes: the option's draft quote, if any, is left in the Quotes hub — deleting quotes is the hub's job. |
| `setOptionQuote(projectId, optionId, quoteId)` | Replaces `setQuote`; mirrors into `doc.quoteId` when `optionId` is `options[0].id`. |

**Existing writes that create members take `optionId`:** `addPlacement`, `addPlacements`,
`addCurtainPlacement`, `addRoute`. They validate the option exists and stamp it. `movePlacement`,
`setPlacementCategory`, `removePlacement`, `removeRoute` are unchanged (they act by id).

**Slicing helper** (pure, `src/lib/design/grid-options.ts`):

```ts
export function optionSlice(p: Pick<GridProject,"placements"|"routes"|"options">, optionId: string)
  : { placements: GridPlacement[]; routes: GridRoute[] }
export function defaultOptionId(p): string   // options[0].id after normalization
```

`grid-bom.ts`, `grid-labor.ts`, `grid-riser.ts`, `grid-curtains.ts` stay pure and untouched —
callers pass them the slice instead of the whole project.

**Callers updated to slice by option:** editor (all BOM/Scope/curtain/labor memos), the
riser page and the schedule page. Both pages accept `?option=<id>`; absent or unknown →
`defaultOptionId`. Existing links keep working.

**Quotes.** `createDraftQuoteAction(projectId, optionId, laborLines?)`:

- Prices only `optionSlice(project, optionId)`.
- Reads/writes `option.quoteId` (update-in-place when a draft already exists, exactly as
  today; re-stamps venue/tier while draft).
- Quote `name`: project name, plus ` · <option name>` when the project has more than one
  option, so "Northshore Main House · Better" is distinguishable on the Quotes hub.
- Quote-cut revision (`reason: "quote"`) unchanged.
- The unresolved-seed-placeholder guard stays (old projects may still hold seeded
  placeholders from D147).

**Deliberately out of scope:** `DesignRecord.budget` is never written for manual designs
today (pre-existing gap, #38 plan recon item 7). Per-option quotes don't worsen it; it stays
for a later item.

## Section 3 — Editor

**Option switcher** in the top bar next to the sheet selector: a segmented control listing
options in order, active one highlighted, each showing its placed-device count. Active
option is held in the URL as `?option=<id>` (`router.replace`, no history spam) so reload,
the Riser link, the Schedule link and quote minting all agree. Missing/unknown → first
option.

Switcher menu (⋯ on the active segment):

- **Add option…** — name field, "Copy current option" checkbox (default on when the current
  option has any placements). Lands on the new option.
- **Rename…**
- **Delete** — confirm bar states "Removes N devices and M wire runs from *Better*. Sheets,
  spaces and other options are untouched." Disabled with tooltip when it is the only option.

**Everything that reads members reads the active option only:** canvas markers, Devices
list, BOM panel, Scope panel placed-vs-target bars, Assemblies panel, Wires panel, curtain
previews, labor hours, price preview, pending-move overlays. Painting a device, dropping a
curtain, or drawing a wire stamps the active option. Spaces, Layers, Sheets, calibration
and Revisions panels are unchanged (shared).

**Scope panel tie-in:** when the active option has `tier`, the Good/Better/Best lens
defaults to that tier on first open for that option. Purely a default; no gating (D139
"goalpost, not gate" holds).

**Removed:** the "Generate starting layout" button, its arm/confirm bar, `pendingSeed`
memo and the `seedStartingLayoutAction` import in `editor.tsx`. The server action and
`src/lib/design/grid-seed.ts` stay (Spec 2 builds the real generator on them); nothing in
the UI calls them after this spec. The `isSeedPlaceholder` marker/detail rendering stays
for old projects.

## Section 4 — Intake, entry points

**Intake becomes two steps** (`grid-intake.tsx`, same route, same first-save gate):

1. **Venue** — venue type cards, size, dimension sliders (unchanged widgets, `DIMSCHEMA`/
   `LIM`/`sizedDims`).
2. **How do you want to design it?** — two cards:
   - **Manual placement** — "Start on a scaled plan and place catalog devices yourself."
     Enabled.
   - **Auto-estimate** — "Good / Better / Best generated from your measurements." Rendered
     greyed with a "Next release" tag; not selectable. (Kept visible so the flow's shape is
     real; enabled by Spec 2.)
   Below the cards: cover-page fields (location/campus, venue/space, address, design notes)
   and **Continue to The Grid →**.

Removed from the intake: systems toggles, starting-tier picker, "Autogenerated brief"
preview, the "Generate from measurements as I work" checkbox. Systems live in the Scope
panel; the base sheet is now always generated from dimensions.

**Intake record** gains `mode: "auto" | "manual"`. `measurementBased` stays `true` on new
saves (kept for compat with `generateBaseSheet`'s gate and old docs). `autoConfig` is still
saved (venue/size/dims over `defaultAState` with the venue preset's `sys`) because
`generateBaseSheet` and `starterSpaces` take an `AState`.

**Save side effects (first save only, as today):**

- `generateBaseSheet(...)` — unchanged. The `seedBlankSheet` branch is removed from
  `saveGridIntakeAction`, and `seedBlankSheet` itself is deleted from the store (verified
  2026-09-21: the intake action is its only caller).
- **New:** write `scopeInputs` from the same venue/size/dims, with the venue preset's
  systems restricted to the five trackable keys, so the Scope panel shows dollar targets
  the moment the editor opens. `TRACKABLE_SYS_KEYS` is today a private const in
  `scope-panel.tsx`; it moves to `src/lib/design/grid-scopes.ts` and is imported by both
  the panel and the intake action.
- **New:** patch the linked `DesignRecord` (found by `gridProjectId`) with `name` (when the
  project was untitled, use "<venue/space> — <location>" or whichever is filled), `venue`,
  `size`, `width`, `depth`, `grid`, so the Designs dashboard card stops rendering
  `? × ? × ?` for manual designs.

Re-saves of venue details (later edits) still don't regenerate the sheet — unchanged gate.

**Entry points — unchanged in this spec.** "New design" keeps its Quick canvas / Manual
layout split. Rerouting it straight to the intake is Spec 2's job: doing it before Auto
exists would remove the only way to auto-estimate a new design. `createManualDesignAction`
is unchanged.

## Data flow summary

```
New design → Manual layout ──► createProject + createDesign(manual)
   └► /design/grid/<id> (intake.complete=false) ──► GridIntake step 1 (venue/dims)
        ──► step 2 (mode=manual + cover page) ──► saveGridIntakeAction
              ├─ generateBaseSheet (sheet + calibration + starter spaces)
              ├─ setScopeInputs (venue/size/dims, trackable sys on)
              ├─ patch DesignRecord dims/name
              └─ options: [ Design ]            (normalized default)
   └► editor ?option=opt-base ──► paint / route (stamped optionId)
        ├─ Add option (copy) ──► second option, independent members
        ├─ Scope / BOM / Riser / Schedule read optionSlice(active)
        └─ Mint quote(option) ──► option.quoteId (mirrored to project.quoteId for options[0])
```

## Error handling

- Option operations return `{ ok:false, error }` for: unknown option, last-option delete,
  empty name, unknown `copyFromOptionId`. Editor surfaces them in the existing error strip.
- `?option=` naming a deleted option → silently falls back to the first option (no error;
  the URL is corrected on next `router.replace`).
- Writes stamping an `optionId` that no longer exists (race: option deleted in another tab)
  are refused by the store; the editor shows "That option was removed — refresh."
- Quote minting on an option with zero members → existing "Place a device or route a wire
  first." message, scoped to the option.

## Acceptance

- Opening a fresh manual design asks only venue type + dimensions, then mode + cover page;
  Continue lands in the editor on a scaled base sheet with Scope targets already showing.
- No "Generate starting layout" button exists in the editor.
- Options can be added (empty or copied), renamed, switched, and deleted (never the last).
  Members never leak between options anywhere in the editor, riser, schedule or BOM.
- Each option mints its own draft quote; the Quotes hub shows them with option names.
- Every pre-existing Grid project opens unchanged with one "Design" option holding all of
  its devices and its existing quote.
- Restoring an old revision still works; restoring a new one brings option names back.
