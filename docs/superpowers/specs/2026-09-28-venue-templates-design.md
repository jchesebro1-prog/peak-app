# Venue templates — stretchable background drawings (design)

**Date:** 2026-09-28 · **Punch:** #249 (recheck the free number on origin/main right before writing docs) · **Branch:** `feat/venue-templates`

## Problem

Every generated plan today is drawn by code (`buildPlanProscenium` in
`src/app/(app)/design/quick/plan-svg.tsx`, sized by `prosGeom`) — a schematic
with guessed seating arcs, doors and a made-up apron bulge. Jeff drew a real
auditorium/PAC background in Vectorworks
(`Dropbox/Template Background-dwg/Template Background.dwg`, copied to
`docs/venue-templates/source/proscenium.dwg`) and wants every proscenium plan
built from it, stretched to the room's typed dimensions. More venue types
(church, gym, black box, …) will arrive as DWGs over time.

## Decisions taken in brainstorming

| # | Decision |
|---|---|
| 1 | Stretchable: the drawing resizes to the typed dimensions. |
| 2 | No stretch layers/classes in the drawing — everything derives from the drawing itself plus Jeff's text labels. |
| 3 | House size gets real inputs: **house width** and **house depth** (option B). |
| 4 | Templates are built into the app (option A): Jeff sends DWGs, Claude converts and commits them. No upload screen in this build. |
| 5 | The pit rectangle is the pit. Pit off → rectangle hidden, the curved line stays as the stage edge. Pit on → pit width keeps its 38/50 share of the proscenium opening. |
| 6 | The template is used **everywhere** the proscenium plan draws: Grid base sheet, Quick Design, saved Designs view. |
| 7 | Quick Design dragging: side walls drag house width, back wall drags house depth; doors are removed for Auditorium/PAC. |
| 8 | Labeled areas become Grid Spaces **and** drive Auto fill placement. |
| 9 | Engine approach: key-line stretch, data-driven (approach 1). |

## What the drawing contains (measured from the DXF)

Units: inches (`$INSUNITS = 1`). All entities sit on one layer (`None`) —
Vectorworks classes did not survive export, so labels are the only semantics.
Entities: 68 LINE, 7 ARC, 2 closed POLYLINE, 7 MTEXT, 34 WIPEOUT (inside
`Group-n` blocks).

| Feature | Drawing value |
|---|---|
| Proscenium opening | x 114.2 → 714.2 = 600" (50') |
| Wings (inside faces) | 180" (15') each; stage wall-to-wall inside 960" (80') |
| Walls | 6" thick throughout |
| Stage depth | proscenium wall (y ≈ 3–9) → stage back wall inner face (y 369) = 30' |
| Pit rectangle | x 186.2 → 642.2 (456", 38'), y −36 → −121.4 (~7'1") |
| Stage edge curve | arc, centre (414.2, 369), r 540.8, 236°→304°; lowest point y ≈ −171.8 |
| Splayed house walls | from (56.5, −81)/(772, −81) out to the side walls at y ≈ −450, then straight to the cross aisle |
| Catwalk | closed band y −223.1 → −279.0 (~4'8"), full width |
| Center Aisle | closed band y −621.0 → −676.8 (~4'8"), full width |
| House back wall | double arc, centre (415.7, 69.7), r 886.8 / 892.8, with entrance gaps |
| House width | inside faces −64.7 → 894.2 ≈ 80' |
| House depth | proscenium line → back wall inner face at centreline ≈ 68' |
| Booth row | MISC Rooms · vestibule · Booth · vestibule · Electrical Room, down to y −949.1 |
| Labels | Stage, Pit, Catwalk, Center Aisle, Booth, Electrical Room, MISC Rooms |

## Architecture

Three units, each testable alone.

### 1. Converter — `scripts/venue-template-convert.py` (dev-time only)

- Input: a DWG (or DXF). Runs LibreDWG `dwg2dxf` (Homebrew `libredwg`), then
  reads the DXF with `ezdxf` (scratch venv, same pattern as
  `scripts/specs-seed-northhs.py`).
- Explodes blocks, drops WIPEOUTs, keeps LINE / LWPOLYLINE / POLYLINE / ARC /
  CIRCLE / TEXT / MTEXT. Output: `src/lib/design/venue-templates/<kind>.json`
  — `{ kind, units: "in", extents, lines[], polylines[], arcs[], labels[] }`,
  coordinates in inches, rounded to 0.01".
- Refuses (non-zero exit, message says why): missing/non-inch units, any
  label listed as required by that kind's key-lines file missing, zero
  drawable entities.
- Also writes a PNG preview next to the JSON for the "does this read right"
  check with Jeff (not committed to `src/`; goes to `docs/venue-templates/`).
- The source DWG is committed under `docs/venue-templates/source/` so the JSON
  can be regenerated byte-identically.

### 2. Key lines — `src/lib/design/venue-templates/<kind>.keys.ts` (hand-written per venue)

Declares, in drawing inches:

- **X key lines** — outer/inner wall faces, proscenium edges, centreline —
  and for each span between them: `fixed` (wall thickness) or which input
  drives it (`proWidth` — split symmetrically about the centreline — or
  `wing`).
- **Y key lines** — stage back wall faces, proscenium wall faces, pit front /
  back, stage-edge low point, catwalk front/back, aisle front/back, back wall
  inner/outer, booth-row bottom — each span `fixed` or driven by `stageDepth`
  or `houseDepth`. House-depth spans are the open house spans only; catwalk
  and aisle bands keep depth and keep their share of house depth.
- **Zones**: the **stage zone** (upstage of the wing-front wall, y ≥ −87)
  uses the stage x-map; the **house zone** uses a y-dependent x-map (below).
- **Named regions** for Spaces / Auto fill: Stage, Pit, House, Catwalk,
  Center Aisle, Booth, Electrical Room, MISC Rooms — each as a polygon of key
  points in drawing inches, plus named lines (plaster line, stage edge,
  catwalk centreline, proscenium edges, centreline).
- **Conditional elements**: entity ids that are the pit (hidden when the pit
  is off).
- **Required labels** (the converter checks these).

### 3. Stretch engine — `src/lib/design/venue-templates/stretch.ts` (pure)

`stretchTemplate(template, keys, dims) → StretchedPlan`

- **Y map**: piecewise-linear through the Y key lines; fixed spans keep
  length, driven spans scale to hit the typed number.
- **X map, stage zone**: piecewise-linear through the X key lines.
- **X map, house zone**: about the centreline. At each y the inside-wall
  half-width is linearly interpolated from the splay start (tied to the
  stage x-map at the wing-front wall) to the house half-width (`houseWidth /
  2`) at the splay end; interior points scale by new/old half-width, points
  outside the inside face translate by the face's delta, so walls keep 6".
- **Curves**: arcs sampled at ≤ 2° steps, each sample mapped, emitted as an
  SVG path — the curve stays smooth under non-uniform stretch.
- **Labels**: anchor point mapped, text size unchanged.
- **Pit**: pit entities omitted when `pit` is off; when on, the pit's x-span
  is `0.76 × proWidth` about the centreline.
- Output: `{ widthIn, heightIn, paths[], labels[], regions: Record<name,
  Point[]>, lines: Record<name, Segment>, warnings[] }` in inches.
- Warnings: `house-narrower-than-stage` when the house width is less than
  the stage wall-to-wall (splays slant inward).

### Integration

- **`prosGeom(s)` becomes template-backed.** Same function name and the
  fields its consumers read (`W`, `H`, `ppf`, `cx`, `yBack`, `yPlaster`,
  `xProcL/R`, `openW`, `stage`, `xAudL/R`, `yHouseFront`, `yBackWall`,
  `boothW/H`, `yBoothBottom`, `yMix`), computed from the stretched plan scaled
  into the existing 640-px-wide canvas. Fields that only served dropped
  features (door arrays, seat rows, apron bulge) are removed and their
  consumers updated. Consumers: `plan-svg.tsx`, `quick-design-client.tsx`,
  `grid-auto-layout.ts`, `grid-projects.ts`, `scripts/test-review-and-spec.ts`.
- **`buildPlanProscenium`** draws the stretched template (plan grey lines,
  labels in the plan's text style) instead of its hand-coded room, then its
  existing overlays on top: line sets, electrics, rigged drapes/legs/borders
  + labels, system symbols, legend, "PLASTER LINE", dimension lines (now also
  house width and house depth). **Dropped** for proscenium: seating arcs,
  door symbols + door handles, the old "PIT" text and apron bulge.
- `renderPlanSvgMarkup` needs no change (paths + texts already supported).
- Church, flat, gym, black box and arena builders are untouched.

## Dimensions and intake

New optional `AState` fields (`src/app/(app)/design/quick/engine.ts`):
`houseWidthFt?: number | null`, `houseDepthFt?: number | null`.

| Input | Drives |
|---|---|
| `width` (pro width) | proscenium opening; pit keeps 76 % of it |
| `wing` | each wing, proscenium edge → stage side wall |
| `depth` (stage depth) | proscenium line → stage back wall |
| `sys.pit` | pit rectangle shown / hidden |
| `houseWidthFt` (new) | inside-face width at the back of the house |
| `houseDepthFt` (new) | proscenium line → back wall inner face at centreline |
| `ph`, `grid` | nothing on the plan |

- **Defaults** (when null): the drawing's own 80' × 68' (exact values taken
  from the key lines). A legacy `houseHalfFt` (Quick Design wall drag) reads
  as `houseWidthFt = 2 × houseHalfFt` when `houseWidthFt` is absent.
- **Clamps**: house depth ≥ 20'; house width ≥ proscenium opening + 2 × wall;
  both ≤ 400'. Typed values outside are clamped, not rejected.
- **Warning** under the fields when the house is narrower than the stage.
- **Where the fields appear**: Grid intake and Quick Design's dimension panel,
  for Auditorium and PAC (any `kind: "proscenium"` venue) only.

## Rendering scope — what changes for existing records

- **Grid**: the base sheet is rendered once at intake and stored as SVG
  (`generateBaseSheet` in `src/lib/stores/grid-projects.ts`), so existing Grid
  designs keep their plan; only new intakes get the template.
- **Quick Design and saved Designs** render the plan live from state, so
  existing proscenium designs there **will** show the new drawing the next
  time they are opened (consequence of decision 6). Their other data is
  unchanged.

## Spaces, Auto fill, scale

- **`starterSpaces`** for proscenium returns, from `regions`: Stage, Pit (only
  when on), House, Catwalk, Center Aisle, Booth, Electrical Room, MISC Rooms —
  replacing Stage / Audience view / FOH / control. Nothing in the code reads
  the old names (checked). Smallest-wins assignment puts a catwalk fixture in
  Catwalk, not House.
- **`venueFrame`** (proscenium) reads `stage`, `audience` (= House) and `booth`
  from the regions, and exposes `catwalk`, `electricalRoom` and the stage-edge
  line. Placement changes in `eachPoints`:
  - `lighting:front` → along the catwalk centreline
  - `audio:mixerDsp`, `video:processor`, `video:projector` → Booth
  - `controls:Processor` → Electrical Room
  - `audio:subwoofer` → along the stage-edge curve
  - everything else keeps today's rule, fed by template-derived rects.
- **Calibration**: the sheet's scale comes from the template's inches (known
  width in feet of the stretched plan), replacing the "first rect = room
  width" heuristic for proscenium.

## Quick Design dragging

- Proscenium handles become: one side-wall handle per side at mid-house
  (drags `houseWidthFt`, symmetric) and one back-wall handle on the
  centreline (drags `houseDepthFt`). Whole-foot snap, same clamps, live
  number update. `houseDragPatch` gains these two handle types.
- Door handles and "add door" are removed for proscenium; church keeps its
  door behaviour.

## Error handling

- Converter fails loudly (see §1); nothing half-converted is written.
- Engine never throws on user input: dims clamp; a template/keys mismatch is
  a developer error caught by the spec harness, not a runtime path.
- If the template module failed to load it is a build error (static import).

## Testing

Spec harness (`scripts/test-review-and-spec.ts`), new block:

1. **Identity** — at the drawing's own dimensions every mapped point is within
   0.1" of the source.
2. **Walls keep 6"** and catwalk / aisle / booth-row depths are unchanged
   under changes to pro width, wing, stage depth, house width, house depth.
3. **Only the intended spans move** (e.g. pro width +10' moves the proscenium
   edges ±5' and nothing upstage of the stage wall changes depth).
4. **Pit** — off removes the pit entities and keeps the stage-edge curve; on
   keeps 76 % of the opening.
5. **Regions agree with placement** — Auto-fill front lights land inside the
   Catwalk Space; booth items inside Booth; the control processor inside
   Electrical Room.
6. **Clamps and warning** — out-of-range inputs clamp; the narrow-house
   warning fires only when house width < stage wall-to-wall.
7. **Converter** — regenerating from `docs/venue-templates/source/proscenium.dwg`
   reproduces the committed JSON; a copy with a required label removed is
   refused.
8. **Legacy** — `houseHalfFt` maps to house width; existing tests on the
   proscenium plan (`gemProsGeom7` et al.) are updated, not deleted; other
   venue kinds render byte-identical.

Beyond tests: side-by-side PNG renders at default / narrow house / wide stage
/ pit off, and a browser pass of a new Grid intake + Auto fill on a scratch
datadir (never `.data/pglite`). Gates per the verification-gate protocol:
tsc, test:specs, test:smoke, eslint vs a baseline, `next build`.

## Out of scope

Upload screen for templates (a later build), seats, doors, templates for
other venue kinds (each arrives as its own DWG + keys file), the section view.

## Adding the next venue type (the repeatable recipe)

1. Jeff sends the DWG with labels on the areas to track.
2. Run the converter → JSON + preview PNG; confirm the preview with Jeff.
3. Write `<kind>.keys.ts` (key lines, spans → inputs, regions, required
   labels).
4. Point that kind's `buildPlan*` / geometry at the template; add its harness
   block (identity, walls, spans).
