# Grid stock symbols — colour by group, icon by category

**Date:** 2026-09-25 · **Status:** approved by Jeff (brainstorm, 2026-09-25) · **Supersedes:** the 8-shape vocabulary of
D154/#131 as the primary look (the shapes stay as a fallback and for back-compat).

## 1. Goal

Anyone looking at a Grid plan or riser can tell **what each device is at a glance**: colour says which system it belongs
to, the glyph says what kind of device it is. Jeff: "tell what the devices are at a glance using color and different
shapes." Per-model artwork (option 2 in the brainstorm) is explicitly out of scope for this spec — a later layer if ever.

## 2. What the user sees

- Every placed device (plan, palette, riser, legends) draws as a **badge**: a rounded rectangle filled with the device's
  **colour**, carrying a white **icon** for its category.
- **Colour resolves group → trade → grey.** The catalog taxonomy (`src/lib/catalog-taxonomy.ts`) gives each category an
  optional *group* (6: Lighting Controls, Fixtures, Video Controls, Speakers, Audio Controls, Curtains) and a *trade*
  (Lighting, Rigging, AV — `tradeOf` already falls back through `GROUP_TRADES`). Rigging hardware (Track, Arbor, hoists…)
  and AV hardware (Networking, Racks, Connectors…) have a trade but no group, so they take their **trade** colour.
  Anything unmapped is neutral grey. That is 6 group colours + 3 trade colours + grey = 10 swatches.
- **Icon resolves per category**, with a generic "device" glyph for any category without one — nothing ever renders
  blank.
- **Per-device override** (the existing per-entry Symbol picker in the Grid editor): choose an icon and, optionally, a
  colour for that one library entry. It wins over the defaults.
- **Grid Settings** (`/design/grid/settings`, admin) replaces the 8-shape card with two cards:
  - **Colours** — the 10 swatches with a colour input each, and "Reset to defaults".
  - **Category icons** — every live category (catalog categories plus Grid library categories), each with its current
    badge preview (in its resolved colour) and a searchable **icon picker** (filter by name and tag). "Reset to
    defaults".
- **Legends**: the riser legend and a small collapsible **plan legend** in the Grid editor (visible in print) list each
  colour/icon combination on the drawing.
- **Defaults ship pre-filled**: every known category (the ~30 in `DEFAULT_CATEGORY_MAP` plus the live Grid categories
  such as Cameras/Video/Speakers/Lighting/Control) maps to a sensible icon, and the 10 colours are distinct and
  colour-blind-safe (Okabe–Ito-based, checked for contrast with the white glyph).

## 3. Icon source and licence

- **Tabler Icons** (`@tabler/icons`, MIT, v3.x, outline set, 24×24 stroke icons). Added as a **devDependency only**.
- A generator script, `scripts/build-grid-icons.ts`, reads a curated pick list (`scripts/grid-icon-picks.json`: tabler
  name → our id, label, tags — about 60–100 entries) from `node_modules/@tabler/icons/icons/outline/*.svg`, reduces each
  SVG to a small element list (path/circle/rect/line/polyline/ellipse with their geometry attributes only), and writes
  `src/lib/design/grid-icons.generated.ts`. Output is deterministic (sorted, stable formatting) and committed. The MIT
  licence text is copied to `LICENSES/tabler-icons.txt` with a header naming the version.
- Runtime ships **only** the curated data — no runtime dependency, no network, no DB, works offline and in the PWA.
- D89 holds: nothing is generated by AI; the pick list is authored by hand.

## 4. Data and resolution (no migration)

All stored values live in the existing settings JSON (like `gridCategoryShapes` today) and on Grid library entries.

- `src/lib/design/grid-icons.ts` (pure, client-safe): the registry `GRID_ICONS` (from the generated file) plus the 8
  legacy shapes registered as icons too, `iconById`, `searchIcons(q)`, `DEFAULT_CATEGORY_ICONS`, `DEFAULT_SYMBOL_COLORS`
  (keys: the 6 groups, the 3 trades, `Other`), `resolveCategoryIcons(stored)`, `resolveSymbolColors(stored)`,
  `cleanCategoryIcons` / `cleanSymbolColors` (validate ids and `#rrggbb`, cap sizes), and the resolver:
  `symbolLook(entry, ctx) → { iconId, color, shape }` where `ctx` = resolved category icons, colours and category map.
- **Resolution order** — icon: entry `icon` → legacy entry `shape` (mapped to its icon alias) → category icon → legacy
  stored `gridCategoryShapes[category]` (alias) → generic device. Colour: entry `color` → group colour → trade colour →
  `Other`. Existing saved plans and per-entry `shape` overrides therefore keep meaning what they meant.
- Settings keys: `gridCategoryIcons: Record<category, iconId> | null`, `gridSymbolColors: Record<key, "#rrggbb"> | null`.
  Stored maps merge **over** the defaults per key (unlike `gridCategoryShapes`, which replaced wholesale), so new
  default categories keep appearing after an admin edits one.
- `GridSymbol` (src/lib/stores/grid-catalog.ts) gains optional `icon?: string` and `color?: string`; `shape` stays.

## 5. Rendering

- `src/components/design/symbol-shape.tsx`: `SymbolShape` / `SymbolIcon` take `{ iconId, color }` (keeping the current
  `shape` prop working as an alias) and draw the badge (rounded rect, `color` fill, subtle darker stroke) with the icon's
  elements scaled into the badge (stroke white, `strokeLinecap/Join="round"`, stroke width tuned so glyphs stay legible
  from 12 px palette size up to plan size). Pure SVG, no `<image>`.
- One renderer used everywhere: plan markers (editor.tsx), palette rows, per-entry picker, riser glyphs and legend,
  Grid Settings previews, the new plan legend.

## 6. Components

- `IconPicker` (client): search box + grid of badges from `searchIcons`; keyboard accessible; used by both Settings and
  the editor's per-entry override.
- Settings cards: `SymbolColorsCard`, `CategoryIconsCard` (replace `GridSymbolsCard`), save through admin-gated actions
  (`requirePerm("manage_users")`, like today) that store cleaned maps and revalidate `/design/grid/settings` and the Grid
  routes.
- Editor: per-entry picker gains icon + optional colour; plan legend panel (collapsible, persisted per browser).

## 7. Testing

- Pure checks: resolution order (entry icon > legacy shape > category > legacy category shape > generic; colour entry >
  group > trade > Other); every `DEFAULT_CATEGORY_ICONS` value and every legacy shape alias resolves to a registered icon;
  `clean*` reject bad ids/colours and cap size; `searchIcons` finds by label and tag; defaults cover every
  `DEFAULT_CATEGORY_MAP` category; colour defaults have ≥ 3:1 contrast against white.
- Generator: running it twice produces byte-identical output; every pick exists in the package; the licence file is
  written.
- Store: `GridSymbol` icon/colour round-trip.
- Gates: tsc, eslint (no new errors), test:specs, test:smoke, and `next build` (client components import only the pure
  module).

## 8. Out of scope

Per-model product artwork; admin SVG uploads (D154 still holds); DaVinci icons (licence, #72); changing catalog
categories themselves.
