# Grid: one sheet per PDF page; a real plan retires the generated plan (#319)

Date: 2026-10-09 · Requested by Jeff · Approved in session ("A, go ahead and implement and push").
Follows #318 (`docs/superpowers/specs/2026-10-09-grid-sheet-crop-rotate-design.md`).

## Asks

1. "When uploads have multiple pages they should be treated as different sheets in the grid."
2. "When a PDF is uploaded it should remove the autogenerated plan set."

## Decisions

- **Split at upload.** Every path that creates a Grid sheet from an uploaded or
  copied file — the `+` tab (broker commit and the legacy 4 MB route), the
  intake Plan view (dropped file and copy-a-plan-on-file), the notices
  re-upload — turns an N-page PDF into **N single-page sheets**, consecutive,
  in page order, at the upload's position (appended, or first for the intake
  plan view). A 1-page PDF and images are unchanged.
  - Names: `<file name> — p.<n>` (n = 1-based); a 1-page PDF keeps its name.
  - Bytes: pdf-lib `copyPages` of page n into a new document (CropBox, MediaBox
    and `/Rotate` carried as the source page has them — inherited values
    resolved, so the new page displays exactly as page n did). Stored like any
    sheet (Blob when on, else data URL within the existing cap).
  - Each split sheet records `split: { from: <original file name>, page: n, pages: N }`
    (display/provenance only) and is its own **root** for #318's Adjust sheet.
  - The original uploaded blob is deleted after a successful split (nothing
    references it; a replayed commit then fails its head read instead of
    splitting twice). On any split failure (encrypted, unreadable by pdf-lib,
    over the page cap) the upload is stored **as one sheet, unchanged**
    (today's behaviour) — never refused for that reason.
  - Cap: at most **60 pages** split per upload; more → kept as one sheet, with
    a note saying why.
  - Existing multi-page sheets are left as they are (they keep page arrows).
- **Adjust queue.** After an upload that produced several sheets, Adjust sheet
  walks them one at a time ("Sheet 2 of 5"), Done or Skip moving to the next,
  with **Skip the rest**. One sheet → today's flow.
- **Retire the generated plan** (Jeff picked option A). After a real plan
  (PDF **or image**) lands through any path above, if `intake.baseSheetId` is
  still listed in `sheetIds` and **no placement or route on any option**
  references it, remove it exactly like Delete sheet (#317): its Spaces go
  with it after an automatic revision (`Auto-saved before removing the
  generated plan`), riser boxes pruned. If it has devices or wires it stays,
  and the upload reports `Generated plan kept — it has N devices on it.`
  (wires counted if no devices). `intake.baseSheetId` is NOT cleared (Auto
  fill keys off it; its refusal already names a missing base sheet).
- Same locking as today: the intake `position: "first"` path stays inside
  `withPlanLock` with `planUploadId` idempotency; split + retire happen inside
  the same commit.

## Surfacing

- Commit / route / copy results gain `sheetIds: string[]` (all new sheets, in
  order) and `baseSheet?: "removed" | { kept: number; what: "devices" | "wires" }`.
  The editor `noteAction`s "Uploaded X as N sheets · removed the generated
  plan" (or the kept sentence); the intake path records the kept sentence as
  an intake notice (existing `GridIntakeNotice` mechanism).

## Testing (`npm run test:specs`, prefix `#319`)

Split: a 3-page pdf-lib PDF (pages with different sizes and one `/Rotate 90`,
one inherited MediaBox) → 3 sheets in order, names `— p.1..3`, each one page,
pdf.js view + rotate equal to the source page's; 1-page PDF and a PNG → one
sheet, name unchanged; encrypted / 61-page → one sheet + note; appended vs
first position; original blob removal on the Blob path (injected remover).
Retire: base sheet with only Spaces → removed + revision cut + Spaces gone;
with a placement → kept + `{kept: 1, what:"devices"}`; no base sheet → no-op;
image upload also retires. Gates: tsc 0, test:specs, eslint, `next build`;
browser check on a scratch datadir with Blob off (multi-page → tabs; queue;
generated plan removed on a Blank design).

## Out of scope

Splitting existing multi-page sheets; choosing which pages to import;
retiring on the Auto path when devices exist.
